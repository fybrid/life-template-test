# Record System

## Collaboration

Treat discussion, planning, inspection, and proposals as read-only work. For a new system or a material change, present a concise proposal and resolve decisions that materially affect the result with the user before making changes, unless the user clearly asks to implement an agreed design.

## Design and Change

Consider only what the requested system needs, such as storage, naming, schema or templates, supported operations, documentation, version-control treatment, and natural-language use. Reuse repository conventions when they fit.

Before changing an existing system, identify relevant records and definitions. Preserve compatibility where practical. Explain the impact of a migration or intentional breaking change and agree on the approach before implementation.

## Audit

When asked to find omissions, inconsistencies, or improvements, inspect and report without modifying files unless the user also asks for changes. Distinguish required corrections, recommended improvements with a clear practical benefit, and optional ideas. Do not expand a system merely for completeness, and say when no meaningful change is needed.

## Skills

Create or extend a skill only for a recurring, repository-specific workflow with a distinct responsibility. Keep it concise and focused on non-obvious decisions and boundaries.

## Boundaries and Verification

Use the relevant domain skill when a request only operates on individual records. After implementation, inspect affected records and definitions for consistency and report the result and any remaining decisions.
